## Friction and actionable citations

1. **The event recipe gives numbers, not an interpretation key.** `human-guide/chapters/03-forensics.md:303` includes 4688 in a filter, but `:308` explains 1102/4720/4781 and some RDP events without explaining 4688, `NewProcessName`, or `ProcessCommandLine`. The recipe at `:302` requires EVTX, while the supplied task is already-exported JSON. Basic file skills recover values; the guide does not answer what those values prove. Add a compact event/field/claim-limit table and one exported-record example.
2. **Duplicate tar recovery lacks a direct subheading and launch contract.** `human-guide/chapters/03-forensics.md:137` is generic Archives. The crucial repeated-name warning at `:148` shares a paragraph with unrelated OOXML advice. The immediately useful Python block at `:151` has a hard-coded input at `:157`, but no save-as/run instruction or explicit output mapping outside the code. I found it by searching and supplied the invocation. Split out a short “Repeated tar names: retain every version” entry.
3. **PNG's extraction succeeds but output inspection is left implicit.** `human-guide/chapters/05-steganography.md:51` provides a strong save/run instruction. `:76` writes `png-parts/trailer.bin` and `:77` reports its length; `:83` says to check various chunk types and bytes after IEND without a direct next command for the generated trailer. One “If trailing bytes > 0, inspect this output” line would shorten the final handoff. This is small friction, not a failure.

Positive environment evidence: `human-guide/chapters/06-reverse-engineering.md:9`, `:14`, and `:15` make the two environments explicit; `human-guide/TOOL-MATRIX.md:32` and `:170` settle the lookup. I did not infer installation or plugin availability from approval.

Prose/actions encountered: PNG heading to runnable instruction was one prose paragraph and no prerequisite detour. Archives heading to generic commands was one environment paragraph; reaching the task-specific script then required passing four generic archive commands and one mixed OOXML/duplicate-tar paragraph. Windows heading to EVTX action was one short environment line, but there was no matching JSON/4688 interpretation action. Reverse environment heading to useful tool table was one paragraph. These are observed content counts, not invented reading times. Long scripts are justified here because they actually worked; the friction is identifying inputs and outputs, not simply line count.

## Top three cuts/restructures

1. Put the process-event row directly beside the numeric event filter: event meaning, named fields, UTC source, and claim limits. Give exported records their own short route.
2. Split archive content into separate “List/test”, “Repeated tar names”, and “Office ZIP contents” entries. Put a filename/run/output line before the duplicate-preserving script.
3. Add the expected output and one next inspection action immediately after each extraction recipe; move broad format caveats below that immediate handoff.

BEFORE, forensics line 148: OOXML guidance and duplicate-tar warning share one paragraph before the script.

Short cheat-sheet alternative (proposal only; guide not edited):

> **Repeated tar names — WSL Python**
> Save the script below as `tar_versions.py`; change `archive.tar.xz` to your evidence filename. Run `python3 tar_versions.py`. Each regular-file occurrence is saved separately as `out/tar-members/000000.bin`, etc. Printed index/name/size maps each output back to its archive member. Read every version; ordinary extraction can overwrite earlier ones.
